# OrderConverterEXE 系统代码逻辑文件（以代码为准）

> 本文档基于 `OrderConverterEXE` 目录下的实际代码整理，用于解释“扫描 → 转换 → Orders 特殊处理 → 采购表生成 → 删除源文件”的全流程与关键规则。

## 1. 系统概述

### 1.1 目标
- 自动扫描 `docs/sourceData/` 下的 `.xlsx` 文件并转换到 `docs/convertedData/`
- 对 `Orders` 目录下的订单文件做增强处理（新增计算列、匹配报价表、输出 Excel）
- 对 `LG-Le/**/Orders/` 额外生成采购表（输出 Excel）

### 1.2 运行形态
- 控制台程序 + `BackgroundService` 后台循环
- 默认每 `10` 秒执行一次扫描（`Configuration.CheckIntervalSeconds`）

## 2. 项目结构与模块职责

### 2.1 `Program.cs`（入口）
- 注册编码：`Encoding.RegisterProvider(CodePagesEncodingProvider.Instance)`
- 启动 Host，注册依赖：
  - `Configuration`：单例
  - `XlsxConverterService`：HostedService
- 日志：
  - Console Logger
  - File Logger：`xlsx_converter.log`（`FileLoggerProvider`）

### 2.2 `Configuration.cs`（路径与间隔）
- `BaseDir`：默认向上回到仓库根目录（用于拼装 docs 路径）
- `SourceDir`：`docs/sourceData`
- `TargetDir`：`docs/convertedData`
- `GetQuotationPath()`：`docs/convertedData/LG-Le/Quotation`

### 2.3 `XlsxConverterService.cs`（核心逻辑）

核心职责：
- 维护后台循环（`ExecuteAsync`）
- 扫描源目录（`ScanAndConvert`）
- 根据路径判定 Orders / 非 Orders
- Orders：生成两份 tracking&cost Excel，并在满足条件时生成采购表
- 非 Orders：按 sheet 生成 CSV
- 批量删除源文件（`DeleteSourceFile`，带重试）

---

## 3. 总体流程（从启动到处理完成）

### 3.1 启动流程
1. `Program.Main` 构建 Host 并运行
2. `XlsxConverterService.ExecuteAsync` 启动
3. `EnsureDirectories()`：
   - 创建 `SourceDir` 与 `TargetDir`
   - 输出运行模式日志（递归扫描/保持结构/转换后删除）

### 3.2 周期扫描流程（每 10 秒）
`ExecuteAsync` 循环：
1. `ScanAndConvert()`
2. `Task.Delay(CheckIntervalSeconds)`

### 3.3 扫描排序与“延迟删除”
`ScanAndConvert()` 关键点：
- **先同步目录结构**：`SyncDirectoryStructure()`（在 target 下创建对应子目录）
- **递归枚举**：`*.xlsx` 与 `*.XLSX`
- **处理优先级排序**（非常关键）：
  - 相对路径包含 `Quotation` → 优先级 0
  - 相对路径包含 `Orders` → 优先级 1
  - 其他 → 优先级 2
  - 目的：尽量保证报价表/找货表先转换为 CSV，后续 Orders 才能读取这些 CSV 做匹配
- **延迟删除**：
  - 每个文件转换成功后仅记录到 `filesToDelete`
  - 本轮扫描所有文件处理完成后，再统一调用 `DeleteSourceFile`

## 4. 单文件转换（`ConvertXlsxToCsv`）

### 4.1 去重/跳过逻辑
以相对路径 `relativePath` 为 key，记录“最后修改时间”：
- 若 `_processedFiles[relativePath] == FileInfo.LastWriteTime` → 认为已处理，跳过
- 若文件被重新复制/修改（最后修改时间变化）→ 重新处理并覆盖输出

### 4.2 Orders 判定
满足任意条件则视为 Orders 文件：
- `relativePath.Contains("Orders", OrdinalIgnoreCase)` 或
- `relativeDir.Contains("Orders", OrdinalIgnoreCase)`

### 4.3 Excel 加载策略（图片异常兜底）
优先用 ClosedXML 直接读取：
- `new XLWorkbook(xlsxFilePath)`

若捕获到图片相关 `ArgumentException`（如 `Picture names cannot be more than 31 characters`）：
- 改用 `LoadWorkbookWithoutPictures()`（OpenXML 读取 cell 数据，跳过图片）构造 `XLWorkbook`

### 4.4 Sheet 遍历与跳过规则
对 `workbook.Worksheets` 逐个处理：
- `RangeUsed == null` → 跳过
- sheet 名包含 `WpsReserved` 或 `Reserved`（不区分大小写）→ 跳过

### 4.5 非 Orders 输出（CSV）
- 输出文件：`{安全文件名}_{安全sheet名}.csv`
- CSV 写出：UTF-8 BOM（`new UTF8Encoding(true)`）
- 字段转义：包含 `,` / `"` / 换行 的字段会用引号包裹，且 `"` 转为 `""`

### 4.6 Orders 输出（两份 Excel）
Orders 对每个 sheet 执行：
1. 生成 base 文件名（与 sheet 名无关）：
   - `{上上级目录} {上级目录} {日期英文} tracking & cost.xlsx`
   - 日期英文：从源文件名提取 `YYYYMMDD`，转为 `Jan23rd`（带 st/nd/rd/th 后缀）
   - 若提取失败：用当天日期
2. 输出 1：`onlyShip_{baseFileName}`
   - 走 `ProcessOrdersFile()` → 使用报价表的 `Ship to XX...` 列
3. 输出 2：`{baseFileName}`
   - 走 `ProcessOrdersFileForTotalToFr()` → 使用报价表的 `Total to {Country}` 列（列名需精确匹配）

> 注意：如果一个 Orders 工作簿包含多个 sheet，会多次写入同名输出文件，后处理的 sheet 会覆盖先生成的文件。

### 4.7 采购表生成（仅 LG-Le Orders）
Orders 输出两份 tracking&cost 后，若满足：
- 相对路径包含 `LG-Le` 且包含 `Orders`（不区分大小写）

则调用 `GeneratePurchaseTable()` 生成采购表：
- 文件名：`{上上级目录} {上级目录} {日期中文} 采购.xlsx`
- 日期中文：`2026年1月23日`（同样从源文件名提取 `YYYYMMDD`）

## 5. Orders 文件数据处理细节

### 5.1 `ProcessOrdersData`（onlyShip 版本）
执行顺序（与代码一致）：
1. `FixMissingProductSku`
2. `RemoveUnnecessaryColumns`（删除 `Item cost`、`Shipping cost`）
3. `AddSkuQuotationColumn`
4. `AddQtyMergedColumn`
5. `AddCostAndUpsellColumns`（基于 `Ship to XX...` 列）
6. `AddSumRow`

### 5.2 `ProcessOrdersDataForTotalToFr`（Total to 版本）
与上面类似，但 cost/upsell 查找使用：
- `AddCostAndUpsellColumnsForTotalToFr` → `Total to {Country}` 列（精确列名匹配）

### 5.3 缺失 `商品SKU` 的修复（`FixMissingProductSku`）
- 需要同时存在：
  - `商品SKU` 列（列名包含“商品SKU”）
  - `Item name` 列（列名同时包含 `Item` 与 `name`，大小写不敏感）
- 构建映射：
  - 对“商品SKU不为空”的行，取 `Item name` 的“主体部分”（去掉颜色/尺寸）作为 key
  - 记录 `主体部分 -> 商品SKU`
- 回填：
  - 对“商品SKU为空但 Item name 不为空”的行，按主体部分查映射并填充

### 5.4 `SKU_Quotation` 生成（`AddSkuQuotationColumn`）
- `SKU_Quotation = ExtractSkuPrefix(商品SKU)`，规则：按 `-` 分割取前两段
- 若同时存在 `SKU` 列且与 `商品SKU` 不是同一列，会用 `商品SKU` 覆盖 `SKU`
- 列位置：放在 `SKU`（或 `商品SKU`）右侧

### 5.5 `QTY_Merged` 生成（`AddQtyMergedColumn`）
- 分组键：`Order#` + `SKU_Quotation`
- `QTY` 解析：`double.TryParse` 后转 `int`
- 仅在每组第一行写入合计，其余为空
- 列位置：放在 `QTY` 右侧

### 5.6 `cost/upsell` 填充（按订单分组）
共同规则：
- 列插入位置：在 `Country/国家` 左侧，且 `upsell` 在 `cost` 右侧
- 处理粒度：按 `Order#` 分组
- 对每个订单：
  - 仅处理 `QTY_Merged > 0` 的行
  - `QTY_Merged` 最大的那一行 → 填 `cost`
  - 其他行 → 填 `upsell`
- 如果缺少报价表或找不到匹配值：
  - `cost`：`报价表文件不存在` / `未找到匹配的数据`
  - `upsell`：`upsell报价表文件不存在` / `未找到匹配的数据`

#### 5.6.1 onlyShip：`Ship to` 列查找（`FindQuotationValue`）
在报价表 DataTable 中：
- SKU 列：第一个列名包含 `SKU` 的列
- 过滤 SKU：要求与 `SKU_Quotation` **精确相等（Trim 后比较）**
- QTY 列：列名包含 `QTY` 且不包含 `MERGED`
- 国家列：寻找列名 `StartsWith("Ship to")` 且包含国家码（如 `FR`）
- 匹配 QTY：任何一个 QTY 列等于目标 qty 即可取值

#### 5.6.2 Total to：`Total to {Country}` 列查找（`FindQuotationValueByTotalToFr`）
区别点：
- 不再找 `Ship to`，而是找列名 **精确等于** `Total to {countryCode}`（大小写不敏感）
- 其余 SKU/QTY 匹配规则与上面类似

### 5.7 `sum` 行与公式（`AddSumRow`）
- 在 `cost` 左侧的列填入 `sum`
- 在 `cost` 单元格填入公式：
  - `=SUM(cost列 2..N)+SUM(upsell列 2..N)`
  - 其中 `N` 为“sum 行上一行”的 Excel 行号（确保不把 sum 行自身纳入求和）

## 6. Orders Excel 输出格式（`SaveAsExcel`）
- 公式：以 `=` 开头的字符串写入 `FormulaA1`
- `cost/upsell` 数值：
  - 能解析为数字时写入数值，并设置货币格式 `$#,##0.00`
  - 文字包含“未找到/不存在”时保留字符串并设置红底白字
- 其他列若包含“未找到/不存在”也会红底白字
- 冻结：`FreezeRows(2)` + `FreezeColumns(1)`
- sum 行高亮：
  - 找到值为 `sum` 的单元格：黄色背景 + 加粗 + 居中
  - `cost` 列同一行：黄色背景 + 加粗
- 自动列宽：`AdjustToContents()`

## 7. 采购表生成（`GeneratePurchaseTable`）

### 7.1 数据准备
1. 从 Orders worksheet 读取为 DataTable
2. 再执行一次 `FixMissingProductSku`（确保 SKU 完整）
3. 定位列：
   - `商品SKU`
   - `QTY`（不包含 `MERGED`）
   - `Product name` / `产品名称`（可选）
4. 按 `商品SKU` 分组汇总 `QTY`，并保存每组的 `ProductName`（取第一个非空）

### 7.2 找货表（CSV）加载
目录：`docs/convertedData/LG-Le/Quotation/`
- 文件筛选：`*.csv` 且文件名包含 `找货` 或 `找货表`
- 取最新文件（按最后修改时间降序）

### 7.3 采购表字段填充
输出 DataTable 列：
`SKU`、`SKU_商品名`、`size`、`图片`、`应采`、`快递单号`、`备注`、`采购链接`

匹配与填充要点：
- size：默认从 SKU 最后一段推断（如 S/M/L/XL/2XL/均码 等）
- 找货表匹配：
  - 取 Orders SKU 的前缀（前两段）作为匹配 key
  - 找货表行也取 SKU 前缀对比（不区分大小写）
  - 命中后可补齐：中文名字、size、图片、采购链接（列名为启发式匹配）
- `SKU_商品名` 生成：
  - `产品中文名字`（来自找货表） + `Product name(去尺寸)`（来自 Orders）
  - 若两者重复/互相包含，则只保留中文名字；否则拼接为 `中文名字-ProductName`

### 7.4 采购表 Excel 输出（`SavePurchaseTableAsExcel`）
- Sheet 名：`采购`
- 第 1 行：`LG-Le-7天库存采购-{baseName}`（合并 1..8 列）
- 第 2 行：固定业务信息（合并 1..8 列）
- 第 3 行：表头（8 列；其中前两列都显示 `SKU`）
- 数据从第 4 行开始
- SUM 行：
  - 标记方式：图片列值为 `SUM`
  - 数量列写入公式 `=SUM(E4:E{last-1})`
  - 整行黄色高亮 + 加粗
- 冻结：前 3 行

---

## 8. 源文件删除策略（`DeleteSourceFile`）
- 统一在本轮扫描结束后删除
- 若文件不存在：跳过
- 删除重试：
  - 最多 5 次
  - 每次间隔 500ms
  - `UnauthorizedAccessException` 视为“被占用”，记录 Warning 并重试

## 9. 关键输入/输出约定汇总

### 9.1 输入
- 所有待转换文件放入：`docs/sourceData/**/**/*.xlsx`

### 9.2 输出
- 非 Orders：`docs/convertedData/**/{name}_{sheet}.csv`
- Orders：
  - `docs/convertedData/**/Orders/onlyShip_{...}tracking & cost.xlsx`
  - `docs/convertedData/**/Orders/{...}tracking & cost.xlsx`
  - （满足条件）`docs/convertedData/**/Orders/{...}采购.xlsx`

### 9.3 报价表/找货表目录（重要依赖）
- `docs/convertedData/LG-Le/Quotation/`
  - `*报价表.csv`（主报价表，不含 upsell）
  - `*upsell*报价表*.csv`（upsell 报价表）
  - `*找货*.csv`（采购表用找货表，取最新）
