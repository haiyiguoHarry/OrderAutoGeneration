# 数据库迁移说明

项目使用 **EF Core 迁移** 管理数据库结构，启动时通过 `MigrateAsync()` 自动应用未执行的迁移。

---

## 一、当前迁移状态

- **仅保留一份初始迁移**：`InitialCreate`（例如 `20260226030407_InitialCreate`），根据当前 `AppDbContext` 一次性建齐所有表。
- 若你**接受清空数据库**：删除数据库（或删除所有表及数据）后，执行一次 `database update` 或直接启动应用即可由迁移建库并执行种子数据。

---

## 二、常用命令（在 HelloOrder 根目录执行）

必须在**包含 `src` 的解决方案根目录**下执行（例如 `E:\...\HelloOrder`），不要进入 `src\HelloOrder.Api` 再执行。

### 1. 安装 EF 命令行工具（仅需一次）

```bash
dotnet tool install --global dotnet-ef
# 若已安装可更新：dotnet tool update --global dotnet-ef
```

### 2. 应用迁移（建库或更新结构）

```bash
dotnet ef database update --project src/HelloOrder.Infrastructure --startup-project src/HelloOrder.Api
```

- 会按顺序执行未应用的迁移，并写入 `__EFMigrationsHistory`。
- 连接字符串来自 **Api** 项目的 `appsettings.json`（或环境）中的 `ConnectionStrings:DefaultConnection`。
- 也可直接**启动应用**，`Program.cs` 中已调用 `await db.Database.MigrateAsync();`，启动时会自动应用未执行的迁移，再执行种子数据。

### 3. 模型变更后：新增迁移

```bash
dotnet ef migrations add <迁移名称> --project src/HelloOrder.Infrastructure --startup-project src/HelloOrder.Api
```

示例：

```bash
dotnet ef migrations add AddSomeNewTable --project src/HelloOrder.Infrastructure --startup-project src/HelloOrder.Api
```

然后执行一次 `database update`（或下次启动应用时自动应用）。

注意：`--startup-project` 是 **HelloOrder.Api**（没有数字 4），写错会报 “Unable to retrieve project metadata”。

## 三、手动 SQL（可选参考）

适用于：未使用迁移时的**补表/补列**参考，或排查问题时对照。正常开发请以 EF 迁移为准。

在 PostgreSQL 中执行以下 SQL（按需调整 schema，默认 public）。

### 1. 新增表 `user_business_assistant`

```sql
-- PostgreSQL 中 EF 创建的表主键列多为 "Id"（带引号），外键需写 "Id"
CREATE TABLE IF NOT EXISTS user_business_assistant (
    business_user_id UUID NOT NULL,
    assistant_user_id UUID NOT NULL,
    created_at TIMESTAMP NOT NULL,
    PRIMARY KEY (business_user_id, assistant_user_id),
    CONSTRAINT fk_uba_business FOREIGN KEY (business_user_id) REFERENCES sys_user("Id"),
    CONSTRAINT fk_uba_assistant FOREIGN KEY (assistant_user_id) REFERENCES sys_user("Id")
);
```

### 2. 订单表 `order` 新增列

```sql
ALTER TABLE "order" ADD COLUMN IF NOT EXISTS last_operator_id UUID NULL;
ALTER TABLE "order" ADD COLUMN IF NOT EXISTS paid_at TIMESTAMP NULL;
```

### 3. 采购单表 `purchase_order` 新增列

```sql
ALTER TABLE purchase_order ADD COLUMN IF NOT EXISTS operator_id UUID NULL;
```

### 4. 商家店铺表 `merchant_shop`

```sql
CREATE TABLE IF NOT EXISTS merchant_shop (
    "Id" uuid NOT NULL,
    merchant_id uuid NOT NULL,
    "Name" varchar(128) NOT NULL,
    "Platform" varchar(32),
    shop_url varchar(512),
    "Remark" text,
    "Status" integer NOT NULL DEFAULT 1,
    created_at timestamp NOT NULL,
    updated_at timestamp NOT NULL,
    CONSTRAINT "PK_merchant_shop" PRIMARY KEY ("Id"),
    CONSTRAINT "FK_merchant_shop_merchant" FOREIGN KEY (merchant_id) REFERENCES merchant("Id")
);
```

### 5. 商品表 `product`

```sql
CREATE TABLE IF NOT EXISTS product (
    "Id" uuid NOT NULL,
    merchant_shop_id uuid NOT NULL,
    "Sku" varchar(64),
    "Name" varchar(256) NOT NULL,
    "Spec" varchar(128),
    image_url varchar(512),
    platform_url varchar(512),
    weight_kg numeric,
    link_1688 varchar(512),
    suggested_purchase_price numeric,
    suggested_sale_price numeric,
    "Remark" text,
    "Status" integer NOT NULL DEFAULT 1,
    created_at timestamp NOT NULL,
    updated_at timestamp NOT NULL,
    CONSTRAINT "PK_product" PRIMARY KEY ("Id"),
    CONSTRAINT "FK_product_merchant_shop" FOREIGN KEY (merchant_shop_id) REFERENCES merchant_shop("Id")
);
```

### 6. 订单表 `order` 新增店铺列、订单项表 `order_item` 新增商品列

```sql
ALTER TABLE "order" ADD COLUMN IF NOT EXISTS merchant_shop_id UUID NULL;
-- 可选：ALTER TABLE "order" ADD CONSTRAINT "FK_order_merchant_shop" FOREIGN KEY (merchant_shop_id) REFERENCES merchant_shop("Id");
ALTER TABLE order_item ADD COLUMN IF NOT EXISTS product_id UUID NULL;
-- 可选：ALTER TABLE order_item ADD CONSTRAINT "FK_order_item_product" FOREIGN KEY (product_id) REFERENCES product("Id");
```

（若 ADD CONSTRAINT 报错，可只执行 ADD COLUMN。）

执行顺序无严格要求；若表名/列名与 EF 模型不一致，请以实际模型为准调整。

---

## 四、小结

| 操作           | 说明 |
|----------------|------|
| 清空库后建表   | 删库或删表后执行 `database update` 或直接启动应用（`MigrateAsync` + 种子）。 |
| 模型有变更     | `migrations add <名称>` → `database update`（或依赖启动时自动迁移）。 |
| 手动 SQL       | 仅作参考，日常以 EF 迁移为准。 |
